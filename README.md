# Учёт заказов «Быстрая доставка»

Внутреннее приложение для учёта клиентов и заказов. Есть два режима: окно на Tkinter и командная строка. Заказы хранятся в SQLite или TinyDB. Выгрузка и загрузка работают и в XML, и в JSON.

## Установка

Нужен Python 3.8 или новее. В папке `delivery_system` выполните:

```bash
pip install -r requirements.txt
```

Остальное уже есть в Python: `sqlite3`, `tkinter`, `argparse`, `logging`, `json`, `xml.etree.ElementTree`.

## Окно

```bash
python main_gui.py
```

Вверху выбирается база: `sqlite` или `tinydb`. Кнопка «Клиенты» открывает список клиентов: добавить, изменить, удалить. Клиента, у которого есть заказы, удалить нельзя.

Главное окно — список заказов:

- «Добавить» и «Редактировать» открывают форму: дата, клиент из списка, статус, товары и сумма;
- «Удалить» убирает выбранный заказ;
- фильтр по статусу и дате (дата в формате `ГГГГ-ММ-ДД`);
- «Показать отчёт» открывает статистику за день, неделю или месяц;
- список «Формат» и кнопки «Экспорт» / «Импорт» работают с XML и JSON.

При первом запуске, если база пустая, в неё записываются несколько клиентов и заказов.

## Командная строка

Команды из задания:

```bash
python main_cli.py report --period month
python main_cli.py export --file orders_backup.xml
python main_cli.py export --file orders_backup.json
python main_cli.py import --file orders_new.xml
python main_cli.py import --file orders_new.json
```

`--period` принимает `day`, `week`, `month` (или `день`, `неделя`, `месяц`).

По умолчанию используется SQLite, файл `data/delivery.db`. Вторая база:

```bash
python main_cli.py --db tinydb report --period week
```

Файл TinyDB: `data/tinydb.json`. Свой путь к базе задаётся параметром `--path`.

Отчёт показывает:

- количество заказов по статусам;
- топ-3 клиента по сумме заказов;
- общую выручку за выбранный период.

В суммы не входят заказы со статусом «отменён».

## Экспорт и импорт

Формат выбирается по расширению файла. В файле лежат клиенты и заказы. При импорте проверяются обязательные поля, дата, статус, товары и совпадение итоговой суммы с товарами. Если заказ ссылается на клиента, которого нет ни в файле, ни в базе, импорт отклоняется. Повторная загрузка того же файла обновляет записи с теми же id.

Пример JSON:

```json
{
  "customers": [
    {"id": 1, "name": "Иван", "phone": "+7", "address": "ул. Ленина, 1"}
  ],
  "orders": [
    {
      "id": 1,
      "customer_id": 1,
      "order_date": "2026-10-07",
      "status": "новый",
      "total": 1500.0,
      "items": [
        {"product_name": "Пицца", "quantity": 2, "price": 750}
      ]
    }
  ]
}
```

Статусы заказа: «новый», «в доставке», «выполнен», «отменён».

## Логи

События пишутся в `logs/delivery.log`: добавление и изменение клиентов и заказов, импорт, экспорт, формирование отчёта и ошибки команд.

## Тесты

```bash
pytest --cov
```

Нужное покрытие — не меньше 60%. Проверяются обе базы, модели, отчёты, XML, JSON и основные действия окна.
